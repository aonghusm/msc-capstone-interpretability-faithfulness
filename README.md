# Evaluating the Faithfulness of Attribution-Based Interpretability Tooling in GPT-2

Code and data for an MSc Computer Science (Artificial Intelligence) capstone project, University of Galway.

**Author:** Aonghus McMahon
**Supervisor:** Jamal Nasir

## Overview

Interpretability tools are increasingly used to explain why a language model produced a particular output, and such explanations are central to arguments about AI transparency and auditing. Efficient attribution-based methods — the class underlying tools such as the LM Transparency Tool — are considerably faster than activation patching, but speed does not guarantee **faithfulness**: that the components highlighted are genuinely the ones driving the behaviour.

This project compares two methods for identifying important attention heads in GPT-2 small, using the Indirect Object Identification (IOI) task, for which a human-validated reference circuit has been published (Wang et al., 2023).

- **Activation patching** — exact, causal, one forward pass per component (144 in total)
- **Attribution patching** — a first-order approximation using one forward and one backward pass

The two are compared on **agreement** (do they select the same heads, and do they recover the published circuit?), **faithfulness** (are the selected heads necessary and sufficient?) and **efficiency** (wall-clock cost).

## Notebooks

Run in order. Each is self-contained and runs in Google Colab on a T4 GPU.

| Notebook | Purpose |
|---|---|
| `01_ioi_baseline.ipynb` | Loads GPT-2 small, builds IOI prompts, confirms the model performs the task using the logit-difference metric |
| `02_patching_and_ablation.ipynb` | Activation-patching baseline and the mean-ablation harness |
| `03_attribution_patching.ipynb` | Gradient-based attribution importances |
| `04_agreement_and_faithfulness.ipynb` | **Definitive results notebook.** Agreement metrics, faithfulness curves, statistical tests and timing |

All four notebooks use the same dataset: 50 name pairs across two templates, giving 100 sentences, with the random seed fixed at 0. Notebook 04 is self-contained and is the source of every figure and result reported in the thesis; notebooks 01–03 build up the components it uses.

## Method summary

- **Model:** GPT-2 small (124M parameters; 12 layers × 12 heads = 144 attention heads), pretrained weights, no fine-tuning
- **Task:** Indirect Object Identification, e.g. *"When Mary and John went to the shop, John gave a drink to ___"* → *Mary*
- **Metric:** logit difference between the correct indirect-object token and the incorrect subject token
- **Ablation:** mean ablation over the clean IOI sentences, applied at all token positions
- **Statistics:** Wilcoxon signed-rank tests on paired per-sentence values, bootstrap 95% confidence intervals (10,000 resamples), matched-pairs rank-biserial effect sizes

## Reproducibility

- Fixed random seed (`0`) throughout
- Environment: Google Colab, NVIDIA T4 GPU
- TransformerLens 3.6.0 · PyTorch 2.11.0+cu128
- The TransformerLens version matters: the notebooks use `utils` and `HookedTransformer.from_pretrained`, both of which are deprecated and scheduled for removal in TransformerLens 4.0. They run with warnings on 3.6.0.
- Data is fully synthetic and generated by the notebooks; no personal data is used
- Every figure and table in the thesis can be regenerated by running the notebooks in order
